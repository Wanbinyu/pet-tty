# 单图桌宠动作：实现、演示与面试说明

这是 pet-tty 的单图动作功能说明。原始核查基线是 `1d6c356865ddd4332a4787be8e118421deb16e8f`；下文区分原有能力、新增实现与后续可选方案。

## 先看演示

- 开发服务：`npm run dev -- --host 127.0.0.1`，访问 <http://127.0.0.1:1420/motion-demo.html>。
- 单文件导出：`npm run demo:bundle -- <目标HTML绝对路径>`，得到可直接双击的 HTML，样图、脚本、样式全部内嵌。
- 导入主应用：选择「从图片生成动作皮肤」，先确认素材能力，再烘焙 PNG。
- 页面预置四种情况：人工标记的自制角色、没有手的团子、未知区域、默认女仆的平面图。最后一个用于说明 SVG 分层能力在栅格化后不会自动保留。
- 8 个状态按钮切换动作；暂停后拖动时间轴观察 24 帧；「烘焙并播放」会用真正的 IndexedDB + PNG 帧播放器播放当前方案的快照；修改标记后需重新烘焙。

素材为本次自制的几何角色、团子以及仓库 MIT 许可下原有的手写女仆 SVG。没有下载外部图片，没有调用付费 API。

## 原来到底实现了什么

| 对象 | 核查结论 | 基线位置 |
| --- | --- | --- |
| 单图等待用户 | 只有整图水平平移 `dx=sin(t·2π)·6`，没有手臂 mask、关节或识别逻辑，不能称作独立挥手 | 基线 `src/skins/spriteSynth.ts:36` |
| 单图成功 | 有整图起跳；名为 `squash` 的值是 1.06，实际 `sx=.94, sy=1.06`，是变窄、变高；并非压扁 | 基线 `src/skins/spriteSynth.ts:39`、`:40`、`:41` |
| 单图工具与测试 | 整图倾斜或上下起伏，没有独立腿部步态 | 基线 `src/skins/spriteSynth.ts:34`、`:37` |
| 默认女仆 SVG | 有独立袖子路径和 CSS `maid-wave`，属于人为绘制的分层动作；原来的袖口与手掌没有和路径一起被动画变换 | `src/skins/vector/maid.ts` 与 `src/styles.css` |
| 原图 image 类型 | 用 CSS 整图动画，与合成 sprite 是不同路径；等待是平移，成功包含起跳。此次没有宣称已把所有 image/CSS 动画重做 | `src/styles.css:1283` 起 |
| 已有动作 PNG 导入 | 可按动作名分组、按帧号排序，再映射到 Agent 状态；这是素材本身包含真实动作帧 | `src/skins/spriteImport.ts:47`、`:73`、`:128` |
| 桌面行走 | 没有自动沿桌面游走的状态逻辑。`setPosition` 用于恢复保存的窗口坐标；拖动窗口是用户操作 | `src/main.ts` 的 `restorePosition` |

单图动作的原技术路线本来就存在：Canvas 对整图做 translate / rotate / scale，烘焙 PNG，存 IndexedDB，再按状态播放。不能把这条已有路线描述成本次从零发明，也不能把整体摇晃描述成自动生成挥手。

## 本次实现

`src/skins/motion.ts` 成为预览与 PNG 烘焙共同使用的渲染器。成功动作采用连续分段曲线：前 20% 时间脚底着地蓄力，`sx>1, sy<1`；中间 60% 腾空并略微拉伸；后 20% 落地压扁并回到静止。脚底留 8 像素余量，避免贴底造成常规倾斜时裁切。

素材能力有三种：

1. `unknown`：不推断部位，只使用整图动作。
2. `none`：用户明确没有可用手腿，仍使用整图动作。
3. `manual`：用户框选手臂、左腿、右腿之一，点击关节，再勾选确认，才启用相应局部动作。自制样图的预设坐标由人工编写，并非模型输出。

区域坐标归一化到原图的 0～1，关节点必须在矩形内。未确认、非有限数、越界、过小区域被拒绝。两个确认区域重叠时，两者都不参与局部切片，避免重复绘制像素。它只能检查几何有效性，不能证明用户真的框中了手臂；语义正确性仍需人工确认。

等待用户时，确认的手臂绕 pivot 独立旋转。工具或测试状态下，确认的左右腿以相反相位摆动，加上画布内部的往返位移和轻微起伏。这是单图刚性切片的步态示意，没有膝盖弯曲、脚底接地约束、朝向切换或桌面路径规划。没有腿时仅显示整图位移，不把它叫真实步行。

主应用的默认女仆已把每侧袖子、袖口、手掌放进同一个 `<g>`，并以 SVG viewBox 中的肩部坐标作为旋转中心，解决只动袖子的脱节。主应用单图导入现在也使用同一套预览/能力确认；Tauri 中打开时临时把窗口扩大到 850×720，关闭后恢复原模式，避免在 210×340 桌宠窗口里挤编辑器。

## Canvas、局部 mask 与 PNG alpha

整图变换可概括为：`T(脚底位置 + 位移) · R(整图角度) · S(形变及适配缩放) · T(源图左上偏移)`。Canvas 的调用顺序决定矩阵组合，绘制点实际先经历右侧的源图偏移，再缩放、旋转并移到脚底锚点。

局部层再叠加 `T(pivot) · R(局部角度) · T(-pivot)`。实际实现先缓存主体和切片；矩形 clip 只提取原图中该部位的现有像素，再用 `clearRect` 从主体移除同一区域，防止一只原地手和一只挥动手同时出现。每帧先画主体，再画局部层。scratch canvas 的最长边限制为 1024 像素，降低大图重复分配成本。

这里的 mask 是人工矩形，不是自动人体分割或任意精细轮廓。若框中混入躯干，旋转时可能出现缺口；原图中被手臂遮挡的身体像素从未存在，Canvas 仿射无法恢复。可靠输入是透明背景、轮廓独立、遮挡较少的部位。复杂情况应改用人工分层、带完整底图的部件素材、已有动作 PNG，或明确引入重绘/修补模型。

渲染器每帧先清空透明画布，不填白色背景；输出 `image/png`，保留 alpha。页面棋盘格是编辑器背景，预览地面阴影也是展示层，它们没有被烘焙到角色 PNG。普通 JPEG 本身没有 alpha，若未经抠图，背景矩形会随角色一起动。

主应用本次单图动作导入只使用本地 `isolateSubjectLocal`，并尊重“仅保留主体”开关。透明图沿 alpha 边界裁切；普通图使用边缘颜色阈值和最大连通域，复杂背景、相近颜色和不连通部件可能处理不佳，预览需要人工检查。演示页面直接保留上传图，不自动抠图。

仓库原有 `isolateSubject` 仍保留在其他像素娃娃路径中：优先尝试 `@imgly/background-removal` 的 `isnet_fp16`，失败再回退本地方法。背景分割只决定前景/背景，不能据此声称它已识别手、腿或关节点。本次演示与单图动作入口不默认下载该模型；项目完整构建仍包含其他既有功能的 ONNX/WASM 依赖。

## 帧序列、事件与生命周期

每个状态 24 帧，24 FPS，循环约 1 秒。对第 i 帧取 `t=i/24`，不重复烘焙 t=1。一个状态内的 `toBlob` 一起发起，再按数组顺序 `Promise.all` 收集；Canvas API 在调用时取得画面快照，浏览器验证确认首帧和中间帧的 PNG 字节不同，避免全部变成最后一帧。Blob 以 `[skinId,state,index]` 存入 IndexedDB；manifest 只记录帧数、fps 和 loop。

事件链为 `AgentEvent.state → applySkinToDom → spritePlayer.setState`。CSS/SVG 皮肤通过 `PET_VISUAL` 切换状态类；sprite 皮肤切换对应 PNG 序列。缺失状态回退 idle，不凭空补造相应动作。合成的 8 个状态仍沿用现有 `AgentState` 协议，没有引入“自动识别动作意图”的模型。

| AgentState | 单图默认反馈 | 有确认部位时 |
| --- | --- | --- |
| idle | 呼吸 | 同左 |
| thinking | 整图倾斜 | 同左 |
| tool_call | 往返位移、轻微起伏 | 可叠加摆腿 |
| editing | 整图轻摆 | 同左 |
| waiting_user | 整图摇摆、轻跳 | 可叠加手臂挥动 |
| running_tests | 较快起伏与位移 | 可叠加摆腿 |
| success | 压扁、腾空、落地 | 同左 |
| error | 短促整图抖动 | 同左 |

播放器已增加 generation 检查：若 IndexedDB 读取还没结束就换皮肤或退出，旧结果直接丢弃，不创建对象 URL，不覆盖新缓存。deactivate 清除 interval、撤销对象 URL、清空缓存和 img.src；非循环序列播放完成也会停止 interval。编辑器 dispose 取消 requestAnimationFrame 并清理 scratch canvas。合成失败会尝试删除已写入的半成品帧。

动作预览按 24 FPS 计算帧，只在帧号变化时重绘 Canvas，避免在 60/120 Hz 显示器上重复绘制同一帧。暂停、拖动逐帧时间轴或切到后台时取消调度；恢复时从当前帧继续，避免后台停留导致时间轴跳变。关闭编辑器还会移除可见性监听，防止后台恢复事件重新启动已经释放的实例。此优化针对动作预览，不代表所有桌面皮肤或原生窗口均经过性能基准测试。

演示的「释放播放资源」还会删除本次临时 IDB 帧。关闭页面时同步释放播放器与预览资源，并发起临时帧删除；浏览器被强制结束时不能保证异步持久化删除完成。对象 URL 本身会随页面销毁被浏览器回收。主应用主动导入的皮肤属于用户保存内容，需要保留，删除皮肤时才删除 IDB 帧。

## 验证与限制

`npm run typecheck`、`npm run build`、`npm run demo:bundle` 通过。`src/motion-demo/verify.ts` 在实际 Chrome 的 Canvas、PNG 解码器、IndexedDB、计时器和对象 URL 上运行，35 项通过；单文件 `file://` 版本也通过相同验证。新增检查覆盖预览帧率、暂停、后台停止、前台恢复与关闭后不再绘制。保持验证页在前台运行；验证使用人工构造的可见性事件检查生命周期，不代表系统级性能基准。

另外通过真实鼠标事件执行拖框、关节点击和勾选确认，验证未确认时降级、确认后启用局部挥手。主应用实际完成透明 PNG 导入预览、取消、再次导入并生成皮肤、恢复默认女仆与删除测试帧；读取到默认 SVG 的 `maid-wave` 动画和 `67px 54px` 肩部 pivot。截图已检查。

验证范围为浏览器 Web 前端；没有运行 Tauri/Rust 原生桌面构建，因此窗口扩大/恢复的原生 API 分支只完成类型与构建检查。未验证 Android 渲染性能，也没有实现 Android 客户端。

尚未实现：自动部位识别、概率置信度、精细自由形状 mask、遮挡修复、生成式补手、多节骨骼、真实转身、完整接地步态、桌面自主导航。未来可按输入能力升级：先支持高质量分层素材与手动多边形 mask，再考虑可选的本地关键点模型；生成式补手需要生成新像素、模型资源、耗时和质量评估，应独立作为可选能力。

## 面试可用表述

> 原来的单图模式已经能用 Canvas 仿射变换烘焙状态帧，但整体位移不等于挥手。我核实并修正了成功动画把纵向拉伸误写为压扁的问题，统一了预览和 PNG 烘焙渲染器，并加入人工矩形 mask、关节 pivot 和确认机制。有可用部位时才旋转局部；缺手、未知或未确认时降级为整图弹跳摇摆。底层用 PNG alpha 和 IndexedDB 管帧，按 Agent 状态切序列，并用 generation 处理异步切皮肤时的旧请求，释放 timer 和对象 URL。这个版本不包含自动骨骼识别、遮挡补全或生成式补手。

迁移到 Android 时可以讨论 Bitmap + Canvas/Matrix、前景透明像素、按生命周期取消动画与解码任务、缓存大小、后台停止刷新和状态订阅，但这些属于技术映射，不应宣称本仓库已实现 Android 版本。
